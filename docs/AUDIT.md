## Findings

Severity scale: **High** = silently removes a guaranteed safety net or breaks documented behavior; **Medium** = meaningful gap that should be scheduled; **Low** = hygiene, latent risk, or minor doc/consistency issue.

### F1 — CI never runs the browser smoke suite (the repo's only executable UI coverage)

**Severity: High**

**Files:** `.github/workflows/ci.yml`, `package.json`, `tests/e2e/numberLineJumper.spec.ts`

**Evidence:**
The `verify` job in `ci.yml` runs exactly: `npm ci`, `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`. The string `test:e2e` appears nowhere under `.github/`. Meanwhile the 14-test Playwright suite is the *only* coverage that exercises the 1,002-line React shell (`src/app/games/NumberLineJumper.tsx`) as a rendered component — the unit tests never render it; several instead assert on its source text (see F4).

**Impact:**
The entire interactive layer — pointer capture, round timers, keyboard handling, live-region announcements, reveal sequencing — can regress invisibly on `main`. This is not hypothetical: the audit found a real runtime bug in the wheel-zoom path (F2) that CI's current shape cannot catch, because the e2e suite has no wheel assertion and CI does not run the suite at all.

**Recommendation (smallest correction):**
Add one step (or a separate job) to `ci.yml`: `npm run test:e2e` with `npx playwright install chromium --with-deps` and a pinned `GAME_NLJ_E2E_PORT`. A separate `e2e` job keeps the fast unit gate independent of browser-infrastructure flakiness. That is the whole change; no source edits required.

### F2 — Explore track-wheel zoom never fires in Chromium; `preventDefault` violates the passive-listener contract

**Severity: Medium**

**Files:** `src/app/games/NumberLineJumper.tsx` (the `onWheel` handler on the Explore track, line 841)

**Evidence:**
Runtime probe against the built production bundle (`vite preview` + Playwright, Chromium 151, viewport scrolled so the track was mid-page):

```text
native wheel events seen: 1 | defaultPrevented count: 0
valuetext changed: true*   (*only because the page scrolled under the pointer)
scrollY before: 705 after: 712 | page scrolled: true
zoom status now: Zoom level 2 of 8   (change came from the prior keyboard zoom, not the wheel)
console messages:
   [error] Unable to preventDefault inside passive event listener invocation.
```

The handler calls `event.preventDefault()` and expects `deltaY` direction to zoom in/out. In React 19, wheel listeners on the root container are registered passively, so the call is illegal (Chromium logs the violation above) and cannot stop the page scroll; the wheel gesture also does not drive `zoomExplore` from a non-passive element-level listener, so zoom level never changes from wheel input. Keyboard, buttons, pinch, and the zoom slider all work.

**Impact:**
The documented GAME-5 wheel-zoom affordance — "Motion Math Zoom's signature mechanic" per the engine comment block — is dead in the primary target browser, and hovering the line while scrolling blocks or degrades the gesture rather than zooming. Degraded affordance, not data loss.

**Recommendation (smallest correction):**
Either (a) attach the wheel handler manually in a `useEffect` via `element.addEventListener("wheel", handler, { passive: false })` with cleanup (~15 lines in one file), or (b) delete the `onWheel` prop and the wheel mention from the zoom help copy. Option (a) preserves the documented behavior; option (b) removes a misleading affordance. Pair with an e2e assertion: wheel over the track → zoom status changes and `window.scrollY` does not.

### F3 — No coverage measurement exists at all

**Severity: Medium**

**Files:** `package.json`, `vitest.config.ts`

**Evidence:**
- No `test:coverage` script: `npm run test:coverage` fails with `Missing script`.
- `npx vitest run --coverage` fails: `MISSING DEPENDENCY Cannot find dependency '@vitest/coverage-v8'` (the package is absent from `package.json` and `package-lock.json`).
- `vitest.config.ts` contains no `coverage` configuration or thresholds.

Unexercised branches confirmed by inspection: `formatDecimal`'s negative-display path (engine.ts), `formatSignedFraction` (engine.ts), the `scorePlacement` zero-span guard (`length === 0`), `targetRevealAnnouncement`'s degenerate-window branch, and the Explore prompt clamp logic in the shell.

**Impact:**
Coverage is unmeasured and unenforceable. Nobody can see these gaps or detect regressions in them; thresholds cannot protect the pure engine, which is the most regression-prone logic in the repo.

**Recommendation (smallest correction):**
Add `@vitest/coverage-v8` as a dev dependency, a `"test:coverage": "vitest run --coverage"` script, and a modest `coverage.include` for `src/lib/**` with initial thresholds. Scope thresholds to `src/lib` only — the engine is fully unit-testable; the shell's coverage is (and should be) the e2e suite's job. No source changes.

### F4 — String-matching "architecture guard" tests give false assurance and resist refactors

**Severity: Medium**

**Files:** `tests/numberLineJumperAggregates.test.ts` ("summary-screen integration", lines 269/277), `tests/numberLineJumperVisitBests.test.ts` ("session-only architecture", lines 229/231/257), `tests/numberLineJumperPrivacy.test.ts` (third test)

**Evidence:**
Six assertions read source files as text and match literal strings/regexes, e.g.:

```ts
expect(shell).toContain("sessionAggregates({ trials })");            // Aggregates 269
expect(shell).not.toMatch(/errorSum\s*\+=/);                         // Aggregates 277
expect(shell).toContain("visitBestsRef.current = result.bests");     // VisitBests 231
expect(source).not.toMatch(/errorSum|reduce\(/);                     // VisitBests 257
```

**Impact:**
Two failure modes in opposite directions:
1. **False breakage:** an innocent refactor (extracting a helper, renaming a local, reformatting) fails CI with no behavior change. Example: renaming the local variable `aggregates` or wrapping `sessionAggregates({ trials })` in a function breaks line 269 while the behavior is identical.
2. **False assurance:** the guards pass while behavior drifts. `not.toMatch(/errorSum\s*\+=/)` happily passes if the shell recomputed the mean via `.reduce((sum, t) => …)` in some other form. A source-text match does not verify the behavior it is named after.

The privacy/no-storage/no-network regex scans (in `numberLineJumperPrivacy.test.ts` and the aggregate/visit-bests modules) are the exception — they enforce a genuine boundary that behavioral tests cannot easily express, and should stay.

**Recommendation (smallest correction):**
Keep the storage/network/identity boundary scans. Delete (or mark `it.fails`-documented) the formatting-sensitive source-text assertions whose behavior is already covered elsewhere — e.g. the visit-bests reload-reset e2e test already proves the session-only seam behaviorally, and the aggregate values are proven by `sessionAggregates` unit tests.

### F5 — `npm run test:ci` does not exist; no single-command verification gate

**Severity: Low**

**Files:** `package.json`, `README.md`

**Evidence:**
`npm run test:ci` fails: `Missing script`. **Recommendation (smallest correction):**
Add `"test:ci": "npm run typecheck && npm run lint && npm test && npm run build"` (extend with the e2e step once F1 lands).

### F6 — Explore prompt RNG and round RNG share one stream; `rngRef` has a latent constant-seed default

**Severity: Low**

**Files:** `src/app/games/NumberLineJumper.tsx` (lines 126, 165, 335–345)

**Evidence:**
- `const rngRef = useRef<() => number>(() => 0.5);` — initialized with a constant. Today no code path generates a target before `prepareRound()` reseeds, so this is latent only; any future early call would silently produce degenerate (always-0.5) targets.
- `newExplorePrompt()` draws its "Find this number" pick from `rngRef.current`, i.e. the same mid-stream mulberry32 sequence the scored round uses. Explore is unscored, so there is no fairness impact, but two conceptually independent randomness surfaces share one seeded stream.

**Impact:**
Cosmetic/latent. No user-visible bug found.

**Recommendation (smallest correction):**
Give Explore its own `mulberry32` ref seeded once in `beginExplore()`, or initialize `rngRef` to `createAdaptiveTargetGeneratorState`-style null and assert in dev that it is seeded before use. Alternatively, leave as-is and add a one-line comment documenting the shared stream as intentional.

### F7 — `pickInt`/`pickFrom` duplicated between `engine.ts` and `shared/rng.ts`; `shuffled` is dead code

**Severity: Low**

**Files:** `src/lib/numberLineJumper/engine.ts` (lines 34–43), `src/lib/games/shared/rng.ts`

**Evidence:**
`engine.ts` defines private, byte-identical copies of `pickInt` and `pickFrom` while re-exporting only `mulberry32` from `@/lib/games/shared/rng` (line 32) with a comment saying the PRNG was "moved to the shared games module." `shuffled` in `rng.ts` has no importer anywhere in the repo.

**Impact:**
Two copies of the same invariant can drift silently (e.g. if `pickInt` gains overflow handling in one file only). Dead code adds review surface.

**Recommendation (smallest correction):**
Import `pickInt`/`pickFrom` from `@/lib/games/shared/rng` in `engine.ts` and delete the private copies (a pure mechanical edit, no behavior change — the functions are identical). Keep or delete `shuffled`: it is declared as a shared primitive for future games, so deletion is optional.

### F8 — Non-deterministic seed seam and untested reveal timers are acceptable but worth noting

**Severity: Low**

**Files:** `src/app/games/NumberLineJumper.tsx` (`newGameSeed`, `revealMs`, `advanceTimerRef`)

**Evidence:**
`newGameSeed()` returns `Date.now() % 1_000_000`. The shell is the correct and only place for impurity (privacy tests forbid `Date.now` in the engine, and the engine tests confirm the engine stays deterministic), but the millisecond truncation means two rounds started within the same millisecond replay identically — irrelevant in practice. The 1.1–1.7 s reveal timers (`revealMs`) are untested; the e2e visit-bests spec takes ~40 s per project mostly waiting them out.

**Impact:**
Minor test slowness; no correctness issue found.

**Recommendation:** Nothing needed now. If e2e duration becomes a problem, expose a test-only `revealMs` scale factor (e.g. via a data attribute read at mount) rather than sleeping less.

### F9 — Accessibility: strong overall, two narrow risks

**Severity: Low**

**Files:** `src/app/games/NumberLineJumper.tsx`, `src/app/globals.css`, `package.json`

**Evidence (positive — say so explicitly):**
- Real `role="slider"` semantics: `aria-valuemin/max/now`, rich `aria-valuetext` (`ariaValueText`), `aria-keyshortcuts`, `aria-orientation`.
- Separate, non-duplicating live regions: the hidden value announcer for marker movement, the `role="status"` feedback panel for the scored reveal (announcements are explicitly cleared to avoid double-speak).
- Focus management: focus moves to the feedback panel on reveal and to the heading on phase change, with `preventScroll`.
- Reduced-motion: CSS `@media (prefers-reduced-motion: reduce)` disables transitions/animations *and* JS branches (`revealMs` and touch-action) honor it.
- Touch targets: 44 px zoom controls, 72 px track height on mobile — asserted by an e2e test.
- `@axe-core/playwright` is a declared dependency.

**Evidence (risks):**
1. `@axe-core/playwright` is installed but never imported anywhere — zero automated axe scans exist. (README defers a11y CI to a later story, so docs match reality; but the unused dependency misleads readers into thinking scans exist.)
2. The playing track sets `tabIndex={committed ? -1 : 0}` + `aria-disabled` while focus is intentionally moved to the feedback panel on reveal. This is coherent, but no automated pass verifies there is no focus trap across the reveal → next-trial cycle.

**Recommendation (smallest correction):**
Add one axe scan to an existing e2e test (`new AxeBuilder({ page }).analyze()` on the setup, playing, and explore views). The dependency is already paid for; it converts the "a11y deferred" risk into a checked invariant at zero new dependencies.

### F11 — Signed-fraction reduction invariant is unpinned by tests (no live bug found)

**Severity: Low**

**Files:** `tests/numberLineJumper.mixed.test.ts` (reduction loop covers unsigned displays only), `src/lib/numberLineJumper/engine.ts` (`formatSignedFraction`)

**Evidence:**
`tests/numberLineJumper.mixed.test.ts` asserts reduced displays for unsigned fractions; signed displays are only shape-checked (`/^−?\d+(?: \d+)?\/\d+$/`). A reduction bug producing e.g. `"−2/4"` would pass. The audit probed g78 signed-fraction displays across many seeds via the deterministic generator and found no unreduced example — the generator's `n % d === 0` skip plus `formatFraction`'s gcd reduction make it effectively unreachable — so this is a test-coverage gap, not a live bug.

**Recommendation (smallest correction):**
Extend the mixed-test reduction loop to strip the `−` prefix before checking (one-line test addition).

### F12 — Error handling / reliability: verified good (no finding)

The shell and engine are unusually well hardened; worth recording because an audit should also report what is right:

- `scorePlacement` clamps out-of-range norms; `normFromClientX` guards `rect.width <= 0` and clamps to [0,1], so NaN cannot reach the scorer from UI input.
- Zero-span guards everywhere: `summarizeRound`, `exploreZoomTicks` ("fails closed" unit-tested), `exploreZoomNormForValue` (midpoint fallback, NaN-safe, unit-tested), `aggregates.sessionAggregates` (malformed records excluded; explicit `null`s, never NaN — unit-tested including `JSON.stringify` containing no "NaN").
- Audio never throws into the game: `getContext` try/catch, `playSoundCue` try/catch, `void context.resume().catch(() => undefined)`, context closed on unmount — all unit-tested with a fake context.
- Timer hygiene: every phase change and unmount clears `advanceTimerRef`; the reveal → advance path mirrors trials into refs so timer callbacks cannot observe stale state (deliberately double-invocation-safe per the in-code comment).
- Adaptive module fails closed on malformed history (`analyzeRecentTrials` with null/undefined/NaN records — unit-tested).
- PRNG extremes are covered: adaptive generation is unit-tested with constant `0` and `0.999999` rng streams across all bands and modes.

## Highest-Value Findings

1. **F1 — CI never runs the e2e suite.** The repo's only executable UI coverage is invisible to the `main` pipeline; every other gate is green while the interactive shell has zero enforcement. One workflow line fixes the largest single gap.
2. **F2 — Explore wheel zoom is broken at runtime** (empirically reproduced, not speculative): the headline GAME-5 affordance silently fails in Chromium and emits a passive-listener console error. Exactly the class of bug the missing e2e wheel assertion would have caught once CI runs e2e.
3. **F3 — No coverage measurement or thresholds.** The 1,210-line pure engine has multiple unexercised branches; without `@vitest/coverage-v8` they cannot be seen or defended against regression.

## Recommended First Task

**Add `npm run test:e2e` as a CI job in `.github/workflows/ci.yml`** — a separate `e2e` job: `npm ci` → `npx playwright install chromium --with-deps` → `GAME_NLJ_E2E_PORT=4190 npm run test:e2e`, keeping the existing `verify` job unchanged.

Rationale: ~10 lines of YAML; no source changes; cannot weaken any existing check; it is exactly the step PARITY already runs manually; and it immediately converts the repo's largest unenforced surface (browser behavior, including a future regression net for F2) into a gated one.

A natural second task: fix the wheel handler per F2 option (a) and add the e2e wheel assertion that would have caught it.
